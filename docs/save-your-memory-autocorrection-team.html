03 / why

왜 만들었나: 자료와 내용을 찾고 기억하기 어려워서

어떤 자료가 어디에 있는지 찾지 못하고, 어떤 내용이 어디에 있는지 기억나지 않는 경우가 많습니다. 이 문제를 해소하기 위해 만들었습니다.

03

도구가 없을 때

  • 폴더 이름과 파일명을 기억하며 여러 위치를 반복 탐색
  • 큰 문서를 열고 필요한 문단을 다시 찾음
  • 답변은 얻어도 원본과의 연결이 끊김
  • 문서 형식이 달라질수록 검색 루틴도 달라짐
→

save-your-memory 이후

  • 자연어 질문을 FTS5 카탈로그에 한 번 던짐
  • 상위 wiki 페이지를 읽고 필요한 근거만 좁힘
  • 답변과 함께 wiki·원본 경로를 확인
  • 변경된 파일만 다시 추출해 운영 비용을 줄임

팀의 기억을 “내가 봤던 파일”에서 “다시 확인할 수 있는 근거”로 바꾸는 것이 핵심입니다.

05 / when

언제 쓰는가: 한 번의 구축, 반복되는 운영

watcher가 계속 도는 방식이 아니라, 필요한 운영 순간에 명시적으로 갱신하고 점검합니다.

05
T0 / 처음최초 인덱싱index가 전체를 스캔하고 wiki·SQLite를 생성합니다.
T1 / 변경증분 갱신size/mtime이 바뀐 파일만 다시 추출합니다. 변하지 않은 페이지는 재생성하지 않습니다.
T2 / 도구읽기 실패 재시도새 PDF·PPT 변환기를 준비한 뒤 --retry-unreadable로 unsupported/error만 재시도합니다.
T3 / 질문검색과 답변자연어 질문을 던지고, 상위 wiki 페이지와 source 경로를 근거로 답변을 받습니다.
T4 / 점검상태·일관성 확인status로 카탈로그 상태를, lint로 누락·고아 페이지를 확인합니다.
explicit refresh / predictable lifecycle
WHEN · index deliberately, ask continuously
06 / retrieval

질문 한 줄이 근거가 되는 과정

검색 계층과 답변 계층을 분리해, Copilot이 먼저 찾고 그 뒤에 설명하게 합니다.

06
01 / ASK질문 그대로 입력

키워드 요약을 임의로 만들지 않고 사용자의 자연어 질문을 그대로 검색합니다.

02 / RETRIEVEFTS5 + BM25

청크를 검색하고 파일별로 합칩니다. 한글은 bigram으로 붙여쓰기 변형도 보완합니다.

03 / VERIFYwiki를 좁혀 읽기

상위 1~3개 wiki 페이지를 읽고 provenance의 원본 경로를 따라갑니다.

04 / ANSWER답변 + Sources

확인된 주장만 말하고 wiki 페이지와 원본 파일을 Sources로 남깁니다.

정확도를 높이는 현재 장치

  • 긴 문서도 32 KiB 청크로 나누고 파일당 최상위 결과 하나로 병합
  • 한글 복합어를 문자 bigram으로 보강
  • AND 매치가 전무할 때만 OR 폴백

답변의 경계

  • 검색 결과에 없는 내용을 추측하지 않음
  • 읽지 못한 파일은 내용을 이해했다고 주장하지 않음
  • 모순된 문서의 정책적 판단은 팀 리뷰 영역
retrieve → verify → cite
HOW · retrieve first, explain second

10 / complete surface

기능은 네 명령으로 나뉩니다

Copilot Chat에서는 자연어로 요청하지만, 내부적으로는 아래 CLI 계약이 실행됩니다.

10 
# 변경분 반영
index --json

# unsupported/error 재시도
index --retry-unreadable --json

# 검색 근거
query "질문" --limit 5 --json

# 상태 / 위키 일관성
status --json
lint --json

index

처음에는 전체, 이후에는 변경 파일 중심. 결과에서 added·updated·unchanged·removed·오류 건수를 확인합니다.

query

질문과 근거를 JSON으로 반환. Copilot은 보통 상위 1~3개 wiki 페이지를 읽습니다.

status / lint

상태 숫자와 위키 일관성을 별도로 점검. 고아 페이지는 사용자 승인 없이 삭제하지 않습니다.

four commands / one operating contract
SURFACE · index / query / status / lint
11 / decision

우리 팀에 도입할 때의 판단 기준

작게 시작해 검색 품질과 근거 연결을 확인한 뒤, 원본 범위를 늘리는 접근이 안전합니다.

11

잘 맞는 경우

  • 문서가 로컬 Windows 폴더에 흩어져 있음
  • 파일 위치와 원본 링크가 중요한 답변을 자주 만듦
  • Python 3.11+와 SQLite FTS5를 사용할 수 있음
  • Copilot/Codex를 답변 계층으로 사용함

기대치를 조정할 경우

  • 이미지 전용 문서는 OCR 없이는 본문 검색이 어려움
  • 변환기 없는 레거시 PPT는 경로·메타데이터 검색만 가능
  • 암호화·손상 PDF나 바이너리 본문을 이해해 주지는 않음
  • 자동 실시간 감시나 문서 간 진실성 판정 도구는 아님
